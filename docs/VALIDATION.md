## Performance findings

See `BENCHMARK.md` and raw `benchmark.json`. Seven scenarios ran for about eight seconds each: overview, overview-to-close zoom, actual boat travel across three geographic chunks, pan cycling, distant jumps, far-origin close view, and repeated coastal zoom. Vsync was enabled. Monotonic wall-clock timestamps measure frame intervals, including initialization in the first interval. Routine statistics exclude the first two seconds of each phase; all-frame maxima are also reported.

Final run: routine scenarios approximately **60 FPS**, routine **p95 16.70–16.71 ms**. Whole-run average including startup: **59.87 FPS**. The initial overview phase had **two frames above 50 ms**, maximum **93.17 ms**; the later scenarios had no >50 ms frames. Peak estimated geographic cache/render memory was **28.68 MiB**, engine static memory **64.42 MiB**, reported video memory **27.20 MiB**. These counters have different scopes and must not be presented as exact process working set or added as independent physical allocations. The boat phase crossed three chunks with zero blocked frames.

Shader disk caching was unavailable under the filesystem sandbox; Godot logged that warning and rendered successfully. The short run supports the routine frame-time and memory targets on this hardware. The strict whole-run >=60 FPS target is **not met when startup is included**. This is not proof of hitch-free sustained traversal, every waterway, every chart-mode view, or every chunk/LOD configuration. Initial loading spikes remain a known issue. Only the default 1,024 m chunk configuration has a graphical benchmark; compare 512/2,048 m alternatives before choosing a production default.

## Remaining acceptance gaps

1. Complete creek/tributary coverage and source-scale accuracy: coastal ENC is insufficient to certify all requested waterways. The four named rivers need detailed upstream coverage audits and additional hydrography.
2. Missing eastern bathymetry remains unavailable. No MLLW-to-NAVD88 conversion or tidal simulation exists.
3. LOD geometry is globally simplified and same-level seams are tested. A full visual transition recording and subpixel displacement audit remain to be completed; no absolute claim of zero coastline motion is made.
4. Collision is a conservative disc against chart polygons; it can reject narrow passages. No grounding/draft model or bridge-clearance model exists.
5. Source composites list contributing rasters but do not yet preserve per-cell survey identity or uncertainty rasters. NOAA composite values are correctly described as interpolated.
6. Manual corrections update query/numeric readouts; the underlying visual texture/contours retain survey values.
7. Windows export added in a follow-up: `BayGame.exe` embeds code/shaders and reads the included `godot/assets/generated` directory. Graphical launch, real map capture and exit code 0 were verified. It is a folder-based distribution, not a single-file map bundle.

The delivered result is a working, measured geographic vertical slice with these explicit gaps, not a declaration that every long-term milestone acceptance criterion is satisfied.
